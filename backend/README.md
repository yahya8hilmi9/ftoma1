# FTOMA / FATOUMA — إعداد Supabase

## الموجود في النسخة
- `schema.sql`: جداول المنتجات والطلبات وتفاصيل الطلبات وحسابات المسؤول، مع سياسات RLS أولية.
- `../js/data/config.js`: رابط المشروع و`publishable key` العمومي.
- `../js/data/supabase.js`: عميل Supabase ودوال فحص الاتصال، جلب المنتجات النشطة، وتسجيل دخول المسؤول مع التحقق من جدول `admin_users`.

## مهم قبل الاستعمال
1. افتح مشروع Supabase وتأكد من تشغيل `schema.sql`.
2. المفتاح الموجود في `config.js` هو publishable key، ويمكن استعماله في الواجهة فقط مع سياسات RLS صحيحة.
3. لا تضع `sb_secret_...` أو `service_role` في ملفات الموقع.
4. دالة `getActiveProducts()` جاهزة لجلب المنتجات، لكن الكتالوج الحالي ما زال محلياً؛ لم يتم تحويل واجهة المتجر بالكامل إلى قاعدة البيانات تلقائياً في هذه المرحلة.
5. لا تسمح بإنشاء الطلبات العامة مباشرةً من المتصفح. قبل البيع الحقيقي، أنشئ Supabase Edge Function تتحقق من الأسعار والمخزون والتوصيل على الخادم ثم تحفظ الطلب.
6. لاستخدام دخول المسؤول: أنشئ المستخدم من Supabase Auth ثم أضف UUID الخاص به إلى `public.admin_users` بعد التأكد من هويته. لا تجعل جدول المسؤولين قابلاً للتعديل من الزوار.

## فحص سريع من المتصفح
افتح الموقع عبر خادم محلي (وليس `file://`) ثم افتح Developer Console ونفّذ:

```js
FATOUMA.supabase.checkConnection().then(console.log).catch(console.error)
```

إذا ظهر خطأ متعلق بالصلاحيات أو الجدول، راجع `schema.sql` وسياسات RLS من Supabase Dashboard.
